# Winget — TCDev.MicaPDF

Automation uses **[WinGet Releaser](https://github.com/marketplace/actions/winget-releaser)** → **[Komac](https://github.com/russellbanks/Komac)** on every published GitHub Release (see [`.github/workflows/winget.yml`](../.github/workflows/winget.yml)).

## One-time setup

1. Merge the **first** package into [microsoft/winget-pkgs](https://github.com/microsoft/winget-pkgs) using [`2.2.0/`](2.2.0/) (or `komac new … --submit` with Scope `user` and versioned URLs).
2. Fork `microsoft/winget-pkgs` under **TCDev69** (same account as this repo).
3. Create a **classic** PAT with `public_repo` scope → repository secret **`WINGET_TOKEN`**.

After that, tagging `v*` and publishing the release (via `build-release.yml`) triggers Komac to open the winget update PR. Manual re-run: Actions → Publish to WinGet → enter tag (e.g. `v2.3.0`).

## Local manifests (`2.2.0/`)

Source of truth for the **initial** submission only. Later versions are generated by Komac in CI — do not hand-edit for new releases.

Installer facts Komac must keep (fix if regenerating):
- `InstallerType: inno`, `Scope: user` (`PrivilegesRequired=lowest`)
- `%LOCALAPPDATA%\Programs\MicaPDF`
- Versioned asset URLs (`…/download/vX.Y.Z/…`), not `/releases/latest/`
- Match only `MicaPDF-Setup-x64.exe` / `MicaPDF-Setup-ARM64.exe`

### Regenerate / validate with Komac

```powershell
# Analyze installers (hash + Inno metadata)
komac analyze --hash .\MicaPDF-Setup-x64.exe

# After the package exists on winget-pkgs, update a version (opens PR with --submit)
komac update TCDev.MicaPDF `
  --version 2.3.0 `
  --urls `
    https://github.com/TCDev69/MicaPDF/releases/download/v2.3.0/MicaPDF-Setup-x64.exe `
    https://github.com/TCDev69/MicaPDF/releases/download/v2.3.0/MicaPDF-Setup-ARM64.exe `
  --submit

winget validate --manifest .\winget\2.2.0
```

## Local install test
